# 회의실 예약 겹침 확인

## 문제 상황

사내 회의실 예약 시스템에서 새로운 회의를 예약할 때, 기존에 예약된 회의 시간들과 겹치는 시간이 있는지 확인하는 기능에 오류가 있습니다.

`schedule.py`의 `is_available()` 함수는 기존 회의 목록과 새로운 회의 시간을 받아, 새 회의가 기존 회의 중 어느 것과도 겹치지 않으면 `True`를, 하나라도 겹치면 `False`를 반환해야 합니다. 하지만 현재 구현은 항상 무조건 예약 가능(`True`)하다고 판단하는 버그가 있습니다.

```text
입력: 기존=[(10, 12), (14, 16)], 새 회의=(11, 13)
현재 결과: True
기대 결과: False
```

---

## 규칙

1. 기존 회의 목록 `existing_meetings`는 `[(시작시간, 종료시간), ...]` 형태의 리스트입니다. (시간은 0부터 24 사이의 정수 혹은 실수)
2. `new_meeting`은 `(새_시작시간, 새_종료시간)` 튜플입니다.
3. 기존 회의와 시간이 일부라도 겹치면 안 됩니다.
4. 단, 어떤 회의의 **종료시간과 동시에 다른 회의가 시작**하는 것은 겹치지 않는 것으로 간주합니다. (예: 기존 10~12, 새 회의 12~14는 예약 가능)
5. 기존 회의 목록이 비어있다면 무조건 예약 가능합니다.

---

## 기대 결과

| 기존 회의(existing_meetings) | 새 회의(new_meeting) | 기대 결과 |
| --- | --- | --- |
| `[(9, 10), (11, 12)]` | `(10, 11)` | `True` |
| `[(10, 12), (14, 16)]` | `(11, 13)` | `False` |
| `[(13, 15)]` | `(12, 14)` | `False` |
| `[(10, 11)]` | `(9, 12)` | `False` |
| `[]` | `(10, 12)` | `True` |

---

## 수정 제한

* `schedule.py`만 수정합니다.
* `is_available()` 함수의 이름, 매개변수와 반환 타입을 변경하지 않습니다.
* 새로운 파일을 추가하거나 기존 파일을 삭제하지 않습니다.
* 외부 라이브러리를 추가하지 않습니다.
